## 1. Keyword Research, Listing Optimization, Rank Tracking

### 1.1 Helium 10

- **Plans & API access — VERIFIED (secondary sourcing, Helium 10 own pages cited by aggregators; direct fetch of helium10.com blocked by network policy).** The Helium 10 REST API is gated to the **Enterprise plan** only, requiring a custom sales conversation — not self-serve. [Does Helium 10 Have an API? (2026)](https://revenuegeeks.com/software/helium-10/api)
- **MCP server — VERIFIED (via search-result excerpts of Helium 10's own MCP landing/blog pages; direct fetch blocked).** Helium 10 shipped an official **MCP connector** in 2026 that exposes Cerebro/Magnet-style keyword data, ad performance, and profitability data to Claude/ChatGPT/Cursor via OAuth, read-only, on-demand (no autonomous polling). It is bundled free with the **Diamond plan** (no separate Enterprise/API purchase needed for MCP access, distinct from the raw REST API which stays Enterprise-gated). [Helium 10 MCP landing page](https://www.helium10.com/tools/mcp/), [Introducing the Helium 10 MCP](https://www.helium10.com/blog/helium-10-mcp/), [Helium10-MCP GitHub](https://github.com/helium10/Helium10-MCP), [Getting Started with Helium 10 MCP](https://kb.helium10.com/hc/en-us/articles/51580564409883-Getting-Started-with-Helium-10-MCP)
- **Implication for a 15-SKU brand:** the MCP path is the practical one — Diamond plan (~$279/mo tier historically; verify current price at purchase, not independently re-verified here) gets programmatic Claude access to Cerebro (keyword research), Magnet (keyword expansion), and rank data without an Enterprise sales contract. The raw Enterprise API is overkill for 15 hero SKUs / 50-60 catalog SKUs.

### 1.2 Jungle Scout

- **API plan gating — VERIFIED (secondary; official junglescout.com blocked by egress policy, so treat as REPORTED pending primary confirmation).** The Jungle Scout API is only available to **Growth Accelerator** and **Brand Owner + CI** plan subscribers — it is not a standalone or entry-tier product. Pricing is **usage-based per API call**, with a **$0.05/request overage** fee above the plan's included call volume. [Jungle Scout API product page](https://www.junglescout.com/products/jungle-scout-api/), [Does Jungle Scout Offer an API?](https://revenuegeeks.com/software/jungle-scout/api)
- **Endpoints — REPORTED:** Sales Estimates, Keyword Historical Search Volume, keyword search estimates, share-of-voice, estimated sales, and pricing-trend endpoints. No official OpenAPI spec was reachable to confirm the full endpoint list; treat exact schema as unverified until pulled from Jungle Scout's own developer portal at signup.
- **Integration path:** no MCP server found for Jungle Scout as of this research (search turned up none); integration is REST-only, usable via Zapier or custom code — an agent would need a thin Python wrapper (fits the existing `httpx`/`supabase-py` sync-layer pattern already in this repo).

### 1.3 DataDive

- **API — REPORTED.** DataDive (a keyword/product-research tool layered on **Keepa and Jungle Scout's own APIs** per its own review coverage) offers an API on **Standard and Enterprise** tiers, delivering niche data, keyword lists, competitor metrics, and rank history — explicitly pitched at flowing into Google Sheets/Airtable-style workflows. [How the Data Dive API Helps Amazon Sellers Scale](https://datadive.tools/data-dive-api/), [Data Dive vs Helium 10](https://avada.io/blog/data-dive-vs-helium-10/)
- Because DataDive's own API is a re-packaging of Keepa + Jungle Scout data, a Habib-scale agent that already licenses Keepa directly gains little marginal value from a DataDive API subscription — worth flagging as **redundant spend** unless DataDive's UI-side scoring/clustering logic (not exposed via API per the docs found) is specifically wanted.

### 1.4 SmartScout

- **API — VERIFIED (via SmartScout's own listed pages, retrieved through search excerpts; direct fetch blocked).** REST-style JSON API, API-key auth, 8 marketplace codes, cursor pagination, sorting/filtering. Covers 42,000+ Amazon subcategories with revenue, seller count, top-brand, and average-price metrics; strongest for products, brands, sellers, subcategories, keywords, search terms, and competitor-ad data. **Access is Enterprise-tier, custom pricing**, layered on top of the standard SmartScout plan (starts at $29/mo for the dashboard-only tier). [SmartScout API Guide](https://revenuegeeks.com/smartscout-api/), [SmartScout APIs page](https://www.smartscout.com/smartscout-amazon-directory/apis), [How to Integrate Amazon Seller Data (SmartScout API Guide)](https://www.smartscout.com/amazon-selling-guides/how-to-integrate-amazon-seller-data-into-your-tech-stack-smartscout-api-guide)
- SmartScout's core value proposition (competitor/seller/brand database at category scale) is built for wholesale/reseller arbitrage discovery across thousands of ASINs — a poor fit for a 15-SKU branded catalog that already knows its competitor set. **Skip candidate.**

### 1.5 SellerApp, ZonGuru, Merchant Words, Scale Insights, Keyword Scout

- **SellerApp — REPORTED.** Markets an "Amazon Seller API" / "Ecommerce Data API" / "Amazon Sales Data API" product family for product data, pricing intelligence, and cross-marketplace insights, but no public pricing, endpoint list, or auth model surfaced in this research; treat as **UNKNOWN** in depth until a sales conversation. [SellerApp Amazon Seller API](https://www.sellerapp.com/amazon-seller-api.html)
- **ZonGuru — UNKNOWN (no API found).** Search surfaced only the dashboard product (product research, listing optimization, keyword research, sales analytics) with no evidence of a public API or MCP integration. Treat programmatic access as **not available** unless a sales contact says otherwise.
- **Merchant Words — UNKNOWN.** No API documentation, pricing, or MCP surfaced in search results despite a dedicated query; Merchant Words has historically been a search-volume-only data licensor (dashboard/CSV export), and nothing found here contradicts that. Needs direct vendor confirmation before ruling in or out.
- **Scale Insights — UNKNOWN.** No API information surfaced. Scale Insights is primarily known as a PPC bid-automation dashboard (not core to keyword research); no evidence of programmatic access.
- **Keyword Scout** is Jungle Scout's keyword tool, not a separate company — see §1.2 for its API status (bundled into the Jungle Scout API's keyword-volume endpoints).

### 1.6 Verdict: worth it for 15 SKUs?

For a 15-hero-SKU / 50-60-catalog-SKU brand that already knows its niche (Middle Eastern specialty foods — not a broad/undiscovered category), **broad product-discovery tools (SmartScout, ZonGuru, Merchant Words) provide little marginal value**. The highest-leverage programmatic keyword source is **free and first-party**: SP-API Brand Analytics Search Query Performance (§2) plus **one** paid rank/keyword tool for competitive keyword gap-finding. Helium 10's MCP (bundled at Diamond) is the best-fit paid layer because it (a) already ships an agent-native MCP interface matching this project's Claude-via-MCP architecture, and (b) bundles Cerebro/Magnet/rank tracking rather than requiring separate subscriptions per function.

### 3.1 Keepa API

- **Coverage — VERIFIED.** Keepa's domain-code map explicitly includes `ca: 6` for amazon.ca alongside `com: 1`, `co.uk: 2`, `de: 3`, `fr: 4`, `co.jp: 5`, confirming full **Canadian marketplace coverage** for price history, offers, deals, and best-seller data — critical since Habib is CA-first. [Keepa API Overview](https://keepa.com/api-docs/), [Keepa Python client docs](https://keepaapi.readthedocs.io/en/latest/index.html)
- **Pricing/tokens — REPORTED (secondary aggregator; keepa.com direct fetch blocked by network egress policy in this session).** No free tier. Entry preset **€49/mo for 20 tokens/minute**, scaling through €459 / €2,499 / €11,099 presets with per-token cost dropping from ~€5.49/100k tokens (Starter) to ~€2.49/100k (Enterprise). One token typically buys the full data set for one product; tokens expire 60 minutes after being generated; custom slider pricing also available; multiple subscriptions can stack on one API key. [Keepa API: Pricing, Tokens & Real Costs 2026](https://revenuegeeks.com/software/keepa/api)
- **MCP — REPORTED.** A community Keepa MCP server exists (`purahmanian/keepa-mcp`), unofficial. [Keepa MCP listing](https://claudemarketplaces.com/mcp/purahmanian/keepa-mcp)
- **Fit:** for 50-60 catalog SKUs with a modest competitor set, the entry €49/mo tier (20 tokens/min ≈ enough for a handful of daily competitor-ASIN pulls plus price-history backfill) is likely sufficient — this is the best-value historical-price-and-BSR data source available and should anchor the Pricing & Market Intel agent's competitor feed.

### 3.2 SP-API Product Pricing API (v2022-05-01) — first-party, free

- **VERIFIED.** Returns `getFeaturedOfferExpectedPriceBatch` — the computed **Featured Offer Expected Price (FOEP)**: the price at or below which a seller's own SKU can expect to win the Buy Box, batched up to 40 SKUs per call (covers Habib's full hero-SKU set in one request), available in all marketplaces except Japan. Response includes FOEP, the competing Featured Offer, and the current Featured Offer. Uses a **dynamic usage plan** that auto-scales rate limits to account history. A `getCompetitiveSummary` operation was also expanded in a Jan-2025 update. [Product Pricing API v2022-05-01 changelog](https://developer-docs.amazon.com/sp-api/changelog/update-product-pricing-api-v2022-05-01-now-supports-the-getfeaturedofferexpectedpricebatch-operation-in-all-marketplaces-except-japan), [Pricing FAQ](https://developer-docs.amazon/sp-api/docs/pricing-faq)
- This is the single most important pricing data source for Habib's agents: it's Amazon's own Buy Box math, free, and directly actionable by a rule-based repricing agent — no third-party estimation error.

### 3.3 ANY_OFFER_CHANGED Notifications — first-party, free (see also §2)

### 3.6 Review Intelligence

- **No official Amazon review-text API exists — VERIFIED, and has been true for 14+ years per multiple sources.** Sellers get **aggregate** review metrics (rating, count, star distribution) via Brand Analytics, but individual review text has never been exposed through SP-API or any official channel. [Is There An Amazon API To Retrieve Product Reviews?](https://tracefuse.ai/blog/is-there-an-amazon-api-to-retrieve-product-reviews/)
- **Scraping legality — VERIFIED direction, REPORTED specifics.** Scraping *publicly visible* Amazon data (titles, prices, ratings, review excerpts on the product page) is generally not a CFAA violation in the US per the *hiQ Labs v. LinkedIn* Ninth Circuit precedent, but it **does violate Amazon's Conditions of Use**, which is a civil contract matter (risk: account/IP action, cease-and-desist), not criminal exposure. [Is Scraping Amazon Legal? What Courts and ToS Really Say](https://thunderbit.com/blog/is-scraping-amazon-legal), [Is Scraping Amazon Legal? The Ethics, Risks, and Consequences](https://www.scrapehero.com/is-scraping-amazon-legal/)
- **Critical 2024-2025 change — VERIFIED (secondary reporting, consistent across multiple independent sources).** On **Nov 5, 2024**, Amazon moved the full paginated `/product-reviews/` history behind a **login wall** for unauthenticated requests. As of **Feb 26, 2025**, even the "8 most recent reviews" preview requires a session cookie. What remains scrapable without login is only the **3-8 featured reviews** on the product detail page plus the aggregate rating/count/star distribution. This materially raises the cost and legal exposure of any full-review-history scraping approach (would require authenticated/logged-in scraping, a clearer ToS violation). [Amazon Review Scraper 2026: 3 Methods](https://fullscraper.com/en/blog/amazon-review-scraper), [How to Scrape Amazon Reviews: 2026 Guide](https://multilogin.com/blog/how-to-scrape-amazon-reviews/)
- **Given this, review scraping is not recommended for Habib's own review monitoring** — the sanctioned path is Brand Analytics aggregate metrics (own products) plus a paid review-alert tool (below) for competitor review-count/velocity signals, which vendors obtain via review-request-triggered opt-in or aggregate-only means.
- **FeedbackWhiz — REPORTED.** Real-time alerts on new reviews, hijackers, Buy Box loss, and listing changes; recently added AI-generated review summaries. [FeedbackWhiz Review 2026](https://sellermetrics.app/feedbackwhiz-review/), [FeedbackWhiz features](https://jordiob.com/amazon-tools/product/feedbackwhiz/)
- **Sellerise — REPORTED.** 39+ alert types spanning listing, Buy Box, feedback, and account-health changes; includes a Review Requester, Review Dashboard, and Review Downloader. [Sellerise Review 2026](https://revenuegeeks.com/software/sellerise)
- Neither tool's public docs confirmed an MCP or programmatic API in this research — both appear to be **dashboard/email/Slack-alert products**, not agent-callable APIs. Treat programmatic access as **UNKNOWN/likely unavailable**; if Habib wants review alerts inside the agent loop, the practical route is Amazon's own Voice of the Customer + Brand Analytics review counts (aggregate, first-party) rather than these tools.

## 4. Repricers and Price Experiments

### 4.0 Important context: Amazon's March 2026 Agent/BSA Policy — VERIFIED (cross-corroborated across 5+ independent secondary sources; Amazon's own Seller Central forum post not directly fetchable, egress-blocked)

Amazon updated its **Business Solutions Agreement (BSA)** with a new **Section 19 "Agent Policy"**, effective **March 4, 2026** (announced Feb 17, 2026 on Seller Central forums, no opt-out — continued use after March 4 = acceptance), governing "any automated software or AI agents" touching Amazon Services, explicitly naming repricers, PPC automation, browser extensions, and fulfillment scripts as in scope. A **90-day transition window** ran to early June 2026, after which Amazon enforces without warning. Baseline obligations for any "Agent": **(1)** self-identify as automated, **(2)** comply continuously, **(3)** cease access on Amazon's request. Specific to pricing automation: **automated repricing through SP-API is permitted** within Amazon's rate/update-interval limits, but agents **may not use scraped competitor data obtained outside official Product Advertising API / SP-API access** to drive pricing decisions, and **price changes exceeding 20% within 24 hours require human authorization**. All automated tools must run through **registered SP-API applications**; browser automation and Seller Central scraping are explicitly prohibited. [Amazon's new AI agent rules shake up sellers before March 4 deadline (ppc.land)](https://ppc.land/amazons-new-ai-agent-rules-shake-up-sellers-before-march-4-deadline/), [Amazon AI Agent Policy: New Automated Seller Rules 2026 (Digital Applied)](https://www.digitalapplied.com/blog/amazon-ai-agent-policy-march-2026-automated-seller-rules), [Amazon BSA Agent Policy 2026 (ecomclips)](https://ecomclips.com/blog/amazon-bsa-agent-policy-2026-what-every-seller-must-do-before-march-4-to-protect-rankings-sales/), [Amazon AI Agent Policy 2026: Rules and Seller Checklist (vozai)](https://www.vozai.net/en/ads-copy/amazon-ai-agent-policy-2026-compliance/)

**This directly validates Habib's existing architecture** (CLAUDE.md §13: agents never hold SP-API write credentials, all pricing/PPC writes gated through human Telegram/dashboard approval in `approval_requests`, Executor is the sole SP-API writer) — the >20%-in-24h human-authorization rule and the ban on scraped-competitor-data-driven pricing decisions are now **contractual requirements**, not just good practice. It also means: **any Keepa-sourced or scraped competitor price signal must be used for human-facing recommendations only, never to auto-trigger a price write** — reinforcing that a rule-based repricer feeding fully-automated price changes is now higher-risk than an agent that always stops at `approval_requests`.

### 4.1 SP-API's own Automated Pricing Rules (native, free) — VERIFIED

Amazon's SP-API exposes a first-party **"Manage Automated Pricing Rules"** workflow: associate a SKU (via the Listings API) to a pricing strategy — featured-offer-matching, lowest-price, external-price, sales-based, or fully custom rules — with **`minimum_seller_allowed_price`** / **`maximum_seller_allowed_price`** guardrails set in the same PATCH call. Amazon then executes the strategy 24/7. Limitations: **no B2B rule support**, and each SKU can hold only **one** rule at a time. [Manage automated pricing rules with SP-API](https://developer-docs.amazon/sp-api/docs/manage-automated-pricing-rules), [New: Automated pricing rules for SP-API changelog](https://developer-docs.amazon.com/sp-api/changelog/new-automated-pricing-rules-for-sp-api)

This is functionally **Amazon's own repricer, free, API-native, and BSA-compliant by construction** (it's the officially sanctioned mechanism). For Habib's ~15 hero SKUs, this — combined with min/max guardrails Rami approves once per SKU — may cover most day-to-day Buy-Box-chasing without needing any third-party repricer subscription at all.

In 2026, MYE supports A/B testing of main images, A+ Content modules, and titles. An agent could still read MYE *results* by having a human relay/paste them, or by scraping the Seller Central UI — which the March 2026 Agent Policy (§4.0) now explicitly prohibits.

### 4.4 Verdict: is a repricer needed?

For a brand-owner catalog with 15 hero SKUs that mostly **owns its own listings** (limited direct Buy-Box competition from other sellers on the same ASIN, unlike arbitrage/wholesale resale), the case for a **paid third-party repricer is weak**:
1. SP-API's native Automated Pricing Rules (§4.1) already provides free, BSA-compliant, guardrail-bound automation for the common cases (featured-offer matching, min/max bounds).
2. The March 2026 Agent Policy specifically restricts *fully automated* price moves >20%/24h and bans scraped-data-driven pricing — the highest-value use case for a paid repricer (aggressive real-time Buy-Box wars) is exactly the use case Habib's human-approval architecture is designed to slow down anyway.
3. A **rule-based proposal agent** — reading SP-API Product Pricing (FOEP, §3.2) + Keepa competitor history (§3.1) + margin floor from `products` — that writes to `approval_requests` for anything outside pre-approved bounds, and only uses SP-API's own Automated Pricing Rules for the pre-approved band, satisfies both the architecture's approval invariant and the new BSA Agent Policy without any repricer subscription.

**Recommendation: skip third-party repricers for now.** Revisit only if/when third-party sellers begin competing directly on Habib's ASINs at scale (hijacking, §6) such that sub-minute reactive repricing becomes necessary.

### 5.2 Agent-Friendly Workflow: Listings Items API + Product Type Definitions API

- **VERIFIED.** Partial listing updates are submitted as **JSON Patch** documents (add/replace/delete whole attributes — patching *within* an attribute's internal structure is not supported, so an agent must always submit the full replacement value for an attribute like `bullet_point` or `ingredients`, not a diff of it). The `patchListingsItem` operation applies these against a SKU. Every payload must conform to the **JSON Schema** returned by the Product Type Definitions API for the specific product type, marketplace, and seller — meaning the correct agent workflow is: **(1)** call Product Type Definitions API to fetch/cache the schema for the product type (e.g., the grocery-relevant type covering `ingredients`, `allergen_information`, `expiration_type`, `country_of_origin`), **(2)** have Claude generate a compliant JSON payload against that schema, **(3)** call `patchListingsItem` (or preview first via the "preview errors before partially updating a listing" endpoint) to write it. [Listings Items API docs](https://developer-docs.amazon/sp-api/docs/listings-items-api), [Mapping product attributes to the Listings Items API](https://developer-docs.amazon/sp-api/docs/mapping-product-attributes), [Preview errors before partially updating a listing](https://developer-docs.amazon.com/sp-api/docs/preview-errors-before-partially-updating-a-listing), [Partially update a listing](https://developer-docs.amazon.com/sp-api/docs/partially-update-a-listing)
- This maps cleanly onto Habib's existing architecture: content-writing agents never need SP-API *write* credentials directly (per CLAUDE.md's access-control table) — the Executor can own the `patchListingsItem` call the same way it owns pricing/PPC writes, gated by an `approval_requests` row of `action_type: "listing_change"` (already specified in CLAUDE.md §7.2).

## Final Report

### Scope and Method

This survey covers seven areas of the Catalog & Brand and Pricing & Market Intelligence tooling landscape for an AI-agent-run Amazon brand: keyword/rank tooling, free first-party SP-API data, competitor/price intelligence, repricers, listing content production, catalog-health/compliance monitoring, and category-specific (Grocery & Gourmet) requirements. Every claim in the full survey (§1-7 above) is tagged **VERIFIED** (confirmed against a primary/official source, even where retrieved via a search-result excerpt because direct site access was blocked by this session's network egress policy for the large majority of vendor and Amazon documentation domains), **REPORTED** (secondary source or vendor marketing, not independently cross-checked), or **UNKNOWN** (not established). Section 7 (category-specific compliance) is the weakest-verified section because the session's web-search budget was exhausted before it could be fully researched; it is flagged for a dedicated follow-up pass rather than filled with unsourced assumptions.

### Overview

Habib Distribution is a Brand-Registry-enrolled, agent-run Amazon brand with ~15 hero SKUs and 50-60 catalog SKUs on Amazon Canada today, a January 2027 US launch, and Walmart later. Its existing architecture (CLAUDE.md) already commits to a strict separation between data-gathering agents (read-only, no SP-API write credentials) and a single Executor service that holds SP-API write credentials and only acts on human-approved `approval_requests` rows. That architecture turns out to matter more than expected: Amazon's new **Section 19 Agent Policy**, added to the Business Solutions Agreement effective **March 4, 2026**, now makes several of Habib's existing design choices — human approval above a threshold, no scraped-data-driven pricing, registered-SP-API-app-only automation — **contractual requirements**, not just internal safety invariants. This is the single most consequential finding of this survey and should inform every purchase decision below.

The second major theme is that **first-party, free data (SP-API Brand Analytics + Product Pricing + Notifications) now covers most of what paid tools historically monopolized** — Search Query Performance, Search Catalog Performance, Featured Offer Expected Price, and push notifications for offer/listing changes are all free, first-party, and directly machine-readable. For a 15-SKU brand that already knows its competitive set (this is Middle Eastern specialty food, not an undiscovered wholesale-arbitrage category), the highest-leverage paid spend is narrow: one keyword/rank tool with agent-native access (Helium 10's MCP), one deep price-history source (Keepa, which explicitly covers amazon.ca), and nothing else in the "SaaS sprawl" of keyword/competitor tools that dominates seller-tool marketing.

Review intelligence has a hard structural limit: **Amazon has never had a public review-text API**, and as of **November 2024 / February 2025** even the previously-scrapable "8 most recent reviews" preview now sits behind a login wall. FeedbackWhiz and Sellerise offer review/hijack alerting but appear to be dashboard/email products without confirmed programmatic APIs. The sanctioned path for Habib is Brand Analytics aggregate review metrics (own products, first-party) — not scraping, and not a paid alert tool, unless SellerSonar's genuine API (Enterprise tier) is specifically wanted for its unified alert taxonomy.

### Repricers and Price Experiments — the Agent Policy Changes the Calculus

Amazon's March 2026 Agent Policy (Section 19 of the BSA) requires: self-identification of automated tools, registered-SP-API-app-only automation (no browser automation, no Seller Central scraping), a ban on using **scraped competitor data** to drive automated pricing decisions, and **human authorization for any price change exceeding 20% within 24 hours**. This is now a contractual obligation, enforced without warning after a 90-day transition window that closed in early June 2026.

Combined with SP-API's own free, native **Automated Pricing Rules** (SKU-to-strategy association with min/max guardrails, executed 24/7 by Amazon itself), the case for a paid third-party repricer (Aura ~$55+/mo, Informed.co $99-147/mo, Feedvisor $100-1,500+/mo) is weak for a brand owner that mostly controls its own Buy Box. **Recommendation: skip paid repricers.** Use SP-API's native pricing rules for the pre-approved band, and route anything outside that band through `approval_requests` — which satisfies both Habib's existing architecture and Amazon's new contractual requirement simultaneously. Revisit only if third-party hijacker/reseller competition on Habib's own ASINs becomes a recurring, high-volume problem.

Manage Your Experiments (A/B testing of images, A+ Content, titles) has no confirmed API — it is a manual, Seller-Central-UI activity best reserved for the 3-5 highest-traffic hero SKUs on a quarterly cadence, with results relayed to the agent by a human rather than scraped (scraping now conflicts with the March 2026 policy).

### Listing Content Production

Amazon's own AI tools — **Enhance My Listing** (keyword/bullet/description suggestions, now with Rufus-formatted Q&A) and **Creative Studio** (conversational ad-creative generation) — are UI-only, with no confirmed API or MCP. This is actually favorable for an agent-run brand: it means Habib's Catalog & Brand agent should generate listing content itself (Claude, grounded in Product Type Definitions API schemas) and write it via the **Listings Items API's JSON-Patch mechanism**, keeping content generation inside Habib's own audit trail rather than depending on a black-box Amazon feature the agent can't call.

CA→US localization is materially more than translation: Canada legally requires **bilingual (English/French) labeling** for food (with Quebec's Charter of the French Language sometimes requiring French precedence), a differently-formatted Nutrition Facts table, and metric-first net-quantity declarations, while the US requires English-only content, a differently-formatted FDA-style Nutrition Facts panel, and typically imperial-first units. Product Type Definitions are fetched **per marketplace**, so CA (`A2EUQ1WTGCTBG2`) and US (`ATVPDKIKX0DER`) schemas must each be independently validated — this is a real engineering task for the January 2027 launch, not a find-and-replace script.

### Catalog Health and Compliance

Amazon's **Listing Quality Dashboard**, updated July 1, 2026, now grades every ASIN on six components (image quality, title compliance, bullet completeness, A+ presence, review-velocity health, attribute completeness) and reportedly **feeds directly into organic rank** — but has **no confirmed SP-API endpoint** to read the score programmatically. This is a genuine blind spot for an agent-run catalog and should be a recurring manual-check item until Amazon exposes it via API. Suppression and hijack detection, by contrast, are well covered for free by **LISTINGS_ITEM_ISSUES_CHANGE** and **ANY_OFFER_CHANGED** notifications respectively — both should feed directly into the existing Listing & Competitor Intel Agent's alert types. SellerSonar offers a genuine third-party API/webhook layer (Enterprise-gated) but mostly duplicates what these two free notification streams already provide; its marginal value is convenience, not new data. Project Zero (counterfeit takedown, 24-48h) and Transparency (physical anti-counterfeiting codes) remain manual, invitation-gated, human-operated programs with no API — the agent's role is limited to detecting trigger conditions and notifying Rami to act.

### Category-Specific Requirements — the Weakest-Verified Section

This research pass exhausted its search budget before fully covering Grocery & Gourmet Food category ungating, meltables policy, and cold-chain FBA requirements — these remain **UNKNOWN** and are flagged for a dedicated follow-up pass, ideally scoped narrowly to Amazon's own category-requirements pages and CFIA guidance rather than general search. What is confirmed: expiration-dated FBA inventory must be pulled ~50 days before expiry (US), allergen labeling is strictly enforced against the ingredient list, dietary/certification claims (Kosher, Halal, Organic, Gluten-Free) require both label presence and underlying regulatory certification, and Canada's bilingual labeling law is CFIA-enforced and Amazon-inherited. Given Habib sells Middle Eastern specialty foods with potential Halal/Kosher certification claims and a January 2027 US launch, **this compliance gap — not tooling — is the highest-priority open item** from this entire survey, because category ungating and certification lead times can gate the launch timeline independent of any software decision.
